# 桌面宠物应用设计规格（Chrome 插件优先，后续扩展 macOS）

**版本**: v2.0  
**日期**: 2026-03-10  
**状态**: Draft for implementation

## 1. 产品目标与边界

### 1.1 目标
打造一个“由用户自家宠物驱动”的虚拟宠物体验：用户上传照片或视频后，系统生成可互动的小宠物角色，具备行走、跳跃、待机等动画行为，并支持逗猫棒等互动道具。

### 1.2 分阶段目标
1. **阶段 A（MVP）**: Chrome 插件，在网页内显示宠物浮层并交互。  
2. **阶段 B（V2）**: macOS 应用，实现系统级桌面宠物（跨应用/桌面显示）。

### 1.3 关键边界（必须明确）
1. Chrome 插件只能运行在浏览器页面内，**不能成为真正系统桌面宠物**。  
2. 真正“全桌面常驻”的体验需要 macOS 客户端实现。  
3. 首版本建议支持单宠物实例，避免状态复杂度过早膨胀。

## 2. 目标用户与核心场景

### 2.1 目标用户
1. 有宠物且愿意上传宠物素材进行个性化体验的用户。  
2. 长时间在浏览器工作/娱乐，希望有陪伴感的轻量用户。

### 2.2 核心使用场景
1. 用户上传宠物图片，快速生成可行动角色并固定在网页右下角。  
2. 用户通过鼠标或道具与宠物互动，宠物做出反馈（追逐、跳跃、休息）。  
3. 用户切换标签页后宠物状态可连续，且能一键隐藏/暂停。

## 3. 功能需求（Chrome MVP）

## 3.1 素材导入与角色创建
1. 支持图片：`jpg/png/webp`，视频：`mp4/webm`。  
2. 上传后执行本地预处理：缩放、裁剪、背景分离（可选）。  
3. 角色创建方式：
   - MVP: 模板骨骼 + 手动关键点编辑（稳定、可控）。
   - 增强版: AI 自动关键点 + 手动校正。
4. 角色保存为 `PetProfile`，支持重复加载。

## 3.2 动画与行为系统
1. 基础状态机：`idle / walk / jump / sit / sleep / chaseToy`。  
2. 随机行为调度：5-20 秒切换一次状态（带权重）。  
3. 基础物理：重力、地面碰撞、水平速度、边界反弹。  
4. 页面边界策略：不遮挡主要输入区，默认停靠底部。

## 3.3 互动系统
1. 鼠标互动：悬停、点击、拖拽逗猫棒。  
2. 道具系统（MVP 仅 1 种）：逗猫棒。  
3. 反馈机制：宠物对互动事件触发动画与音效（音效默认静音）。

## 3.4 浮层与控制
1. 浮层可拖动、最小化、关闭、锁定位置。  
2. 每站点可单独开关（白名单/黑名单）。  
3. Popup 中可快速切换角色、显示状态、电量友好模式。

## 3.5 数据与配置
1. 本地存储（IndexedDB + chrome.storage）。  
2. 保存角色配置、关键点、行为参数、用户偏好。  
3. 提供“清空本地数据”与“导出/导入配置”。

## 4. 非功能需求（可量化）

| 类别 | 指标（MVP） |
|---|---|
| 帧率 | 常规页面 >= 50 FPS（目标 60 FPS） |
| 启动时间 | 已有角色时，进入页面后 <= 1.0s 出现宠物 |
| 资源占用 | 平均 CPU < 8%，内存 < 180MB（1080p 常规场景） |
| 稳定性 | 连续运行 8 小时无崩溃、无明显内存泄漏 |
| 隐私 | 素材默认仅本地处理，不上传云端 |
| 兼容性 | Chrome Stable 最近两个大版本 |

## 5. 技术架构设计（Chrome）

## 5.1 扩展架构（Manifest V3）
1. `Popup/Options`：上传、编辑、配置。  
2. `Content Script`：注入宠物层（建议 Shadow DOM 隔离样式）。  
3. `Service Worker`：事件总线、配置读取、跨标签页状态协调。  
4. `Offscreen Document + Web Worker`：重计算任务（视频抽帧、模型推理）。

## 5.2 运行时模块
1. `Asset Pipeline`：解码素材、抽帧、压缩、缓存。  
2. `Rigging Engine`：骨骼绑定、关键点编辑、姿态插值。  
3. `Animation Engine`：Canvas2D（MVP）或 WebGL（后续性能优化）。  
4. `Behavior Engine`：有限状态机 + 权重调度 + 冷却机制。  
5. `Interaction Engine`：鼠标事件、道具命中检测、反馈触发。

## 5.3 AI 支持策略（渐进式）
1. MVP 优先手动关键点，减少 AI 依赖和模型体积风险。  
2. V1.1 增加本地 AI：
   - 抠图：U2Net/类似轻量模型（ONNX Runtime Web）。
   - 姿态估计：宠物关键点模型（若精度不足则继续手动校正为主）。
3. 视频支持先做“关键帧提取 + 半自动绑定”，避免直接端到端生成造成质量不可控。

## 6. 数据模型（建议）

```json
{
  "petId": "uuid",
  "name": "Momo",
  "type": "cat",
  "asset": {
    "sourceType": "image",
    "sourceRef": "indexeddb://pet/uuid/source",
    "atlasRef": "indexeddb://pet/uuid/atlas"
  },
  "rig": {
    "joints": [{ "id": "head", "x": 0.51, "y": 0.18 }],
    "bones": [{ "from": "neck", "to": "head" }]
  },
  "behavior": {
    "energy": 0.6,
    "curiosity": 0.8,
    "schedule": { "idle": 0.35, "walk": 0.3, "jump": 0.2, "sleep": 0.15 }
  },
  "ui": {
    "position": { "x": 0.88, "y": 0.82 },
    "scale": 1.0,
    "muted": true
  }

```

## 7. 安全、隐私、合规

1. 权限最小化：仅申请必要权限（`storage`, `activeTab` 等）。  
2. 默认离线本地处理，不上传宠物素材。  
3. 明确告知用户：素材只保存在本机，可随时删除。  
4. 若未来引入云端模型，需增加显式同意和隐私政策更新。  
5. 内容安全：防止页面脚本直接访问宠物原始数据（隔离上下文）。

## 8. macOS 版本演进设计

## 8.1 能力提升目标
1. 全局桌面显示（跨应用，不局限浏览器）。  
2. 系统级悬浮、穿透点击、Dock/Menu Bar 控制。  
3. 开机自启动、低功耗模式、后台常驻。

## 8.2 架构建议
1. 提炼共享核心：`pet-core`（动画状态机、行为逻辑、数据模型）。  
2. 壳层方案：
   - 快速落地：Tauri + WebView（复用前端逻辑高）。
   - 高性能长期：Swift + Metal（渲染/能耗更优）。
3. 数据兼容：Chrome 与 macOS 统一 `PetProfile` 格式，支持迁移导入。

## 9. 开发里程碑（建议 10-12 周）

1. **W1-W2**：基础框架 + 浮层注入 + 本地存储。  
2. **W3-W4**：上传流程 + 手动关键点编辑 + 角色持久化。  
3. **W5-W6**：状态机与动画系统 + 基础互动（点击/悬停）。  
4. **W7-W8**：逗猫棒道具 + 性能优化 + 崩溃恢复。  
5. **W9-W10**：测试、灰度发布、收集反馈。  
6. **W11-W12（可选）**：AI 自动关键点 PoC + macOS 技术验证。

## 10. 技术支持与团队配置

1. 前端/插件工程：TypeScript、Vite、MV3、Canvas/WebGL。  
2. 本地多媒体：`ffmpeg.wasm`（视频抽帧）、`OffscreenCanvas`。  
3. AI 推理：`onnxruntime-web` + 轻量模型管理。  
4. 测试体系：Vitest（单测）、Playwright（扩展 E2E）、性能基准脚本。  
5. 设计支持：宠物动作模板、道具交互设计、动效规范。  
6. 产品运营：反馈采集、崩溃日志、A/B 行为参数调优机制。

## 11. 关键风险与规避

1. **AI 精度不稳定**：MVP 以手动绑定兜底。  
2. **性能超预算**：先 Canvas2D，再逐步迁移 WebGL。  
3. **页面兼容冲突**：Shadow DOM + z-index 策略 + 网站黑名单。  
4. **用户预期错位**（以为是系统桌宠）：产品页明确“Chrome 内宠物”定位。

## 12. 建议的首版取舍（务实版）

1. 先做图片上传，不做视频端到端动画生成。  
2. 先做单宠物，不做多宠物协同。  
3. 先做手动关键点，不依赖重模型。  
4. 先做一个道具（逗猫棒），用真实互动验证留存。
