# 桌面宠物项目实施计划（Chrome -> macOS）

**日期**: 2026-03-10  
**目标**: 先完成 Chrome 插件 MVP，验证核心体验后扩展到 macOS 系统级桌宠。  

## 1. 交付策略

1. **先可用再智能**：先保证上传-生成-互动闭环可用，再引入 AI 自动化。  
2. **先浏览器内验证留存**：互动频次、使用时长、7 日留存达标后再投入桌面端。  
3. **统一核心模型**：`PetProfile` 和行为引擎提前抽象，减少跨平台重写。

## 2. 项目阶段与验收

## 阶段 A（W1-W2）：Chrome 插件骨架

### 范围
1. MV3 工程结构。  
2. Popup（上传入口）+ 内容脚本浮层注入。  
3. 本地存储与基础配置读写。

### 验收标准
1. 扩展可在 Chrome Stable 安装并运行。  
2. 在常见网站可显示/隐藏宠物层。  
3. 数据重启浏览器后可恢复。

## 阶段 B（W3-W4）：角色创建与绑定

### 范围
1. 图片上传与预处理（缩放、裁剪、缓存）。  
2. 手动关键点编辑器（骨骼绑定）。  
3. 保存为 `PetProfile` 并可重复加载。

### 验收标准
1. 用户可在 3 分钟内完成一次角色创建。  
2. 角色绑定后可进入基础动画播放。  
3. 异常素材（超大图/损坏图）有友好报错。

## 阶段 C（W5-W6）：动画与行为系统

### 范围
1. 状态机：`idle/walk/jump/sleep`。  
2. 基础物理：重力、碰撞、边界处理。  
3. 行为调度器（带随机权重）。

### 验收标准
1. 常规页面帧率 >= 50 FPS。  
2. 连续运行 2 小时无明显卡顿。  
3. 行为切换自然、无明显“抽搐”动作。

## 阶段 D（W7-W8）：互动系统与体验完善

### 范围
1. 道具系统（逗猫棒）。  
2. 点击/悬停反馈、音效开关。  
3. 浮层操作（拖动、最小化、站点开关）。

### 验收标准
1. 互动链路延迟 < 100ms（输入到动画反馈）。  
2. 用户可在任意页面快速暂停/关闭宠物。  
3. 黑名单站点不注入宠物层。

## 阶段 E（W9-W10）：测试、发布、数据闭环

### 范围
1. 自动化测试与手工兼容测试。  
2. 崩溃日志与性能指标采集（本地或匿名）。  
3. 小范围灰度发布。

### 验收标准
1. 核心流程 E2E 通过率 >= 95%。  
2. 关键崩溃问题清零。  
3. 拿到首轮用户反馈并形成 V1.1 清单。

## 阶段 F（W11-W12）：AI 增强 + macOS 技术验证（可选）

### 范围
1. AI 自动关键点 PoC（本地推理）。  
2. 背景分离 PoC。  
3. macOS 壳层 PoC（Tauri 或 Swift）。

### 验收标准
1. AI 结果可被手动校正并稳定落库。  
2. macOS 版本能显示同一 `PetProfile` 角色并执行基础状态机。

## 3. 技术工作分解（按模块）

## 3.1 插件端
1. `popup`：上传、配置、角色切换。  
2. `content`：宠物渲染层、交互事件。  
3. `service worker`：全局消息、配置同步。  
4. `storage`：IndexedDB + chrome.storage 分层存储。

## 3.2 引擎层
1. `asset pipeline`：素材预处理、缓存、版本管理。  
2. `rigging engine`：关键点编辑、骨骼约束。  
3. `animation engine`：插值、混合、渲染调度。  
4. `behavior engine`：状态机、冷却与随机权重。

## 3.3 测试与质量
1. 单测：状态机、存储、关键算法。  
2. E2E：上传->创建->互动->持久化。  
3. 性能：FPS、CPU、内存、冷启动时间。

## 4. 依赖与技术支持清单

1. 语言与构建：TypeScript + Vite。  
2. 渲染：Canvas2D（MVP），可演进 WebGL。  
3. 视频处理：ffmpeg.wasm（可选，阶段性引入）。  
4. AI 推理：onnxruntime-web（V1.1 起）。  
5. 测试：Vitest + Playwright。  
6. CI：GitHub Actions（lint/test/build）。

## 5. 团队配置建议（最小）

1. 1 名前端/插件工程师（MV3 + UI + 交互）。  
2. 1 名图形/动画工程师（状态机与渲染）。  
3. 1 名产品/设计（交互、动效、用户反馈）。  
4. 0.5 名测试支持（兼容与回归）。

## 6. 风险与应对

1. **模型效果不稳**：先手动绑定，AI 作为增强而非前置依赖。  
2. **性能瓶颈**：分层降级策略（帧率/特效/分辨率）。  
3. **站点冲突**：Shadow DOM 隔离 + 黑名单机制。  
4. **定位混淆**：在产品文案中明确“Chrome 内桌宠”。

## 7. 里程碑决策门槛（Go/No-Go）

1. W4 决策点：角色创建完成率 >= 70%。  
2. W8 决策点：日均互动次数达到目标阈值（由产品定义）。  
3. W10 决策点：留存达标后启动 macOS 正式开发。
